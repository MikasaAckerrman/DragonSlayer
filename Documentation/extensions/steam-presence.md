# Steam presence — «Играет в Counter-Strike» прямо из игры

## Что это

Зелёный статус в профиле Steam, пока идёт игра на телефоне. Появляется при
входе на карту, гаснет при выходе. Десктопный Steam не нужен.

Статус — это не функция клиента Steam, а одно protobuf-сообщение
`ClientGamesPlayed` (EMsg 742) в авторизованной сессии с CM-сервером.
Кто залогинился по официальному протоколу — может его отправить.

## Почему кнопка «Steam account» раньше этого не давала

| Что было | Что делает | Даёт статус? |
|---|---|---|
| `SteamLoginActivity` + `cl_steam_login.c` | Steam **OpenID 2.0** в WebView, из ответа берётся только `claimed_id` → SteamID64 | нет: это удостоверение личности, а не сессия. Ни токена, ни прав на запись |
| `SteamAPIHelper` | `GetPlayerSummaries` по Web API ключу — чтение аватарок | нет |
| `cl_steam.c` (Steam Broker) | TCP к ПК с настоящим Steam за auth-тикетом для secure-серверов | нет, и требует ПК |

Кнопка работала честно — её максимум и есть SteamID. Отсюда следствие, которое
видно в интерфейсе: аккаунт, вошедший по-старому, показывает аватарку и **не**
может показать статус. Поэтому переключатель в настройках пишет об этом прямо,
а не молча ничего не делает.

## Архитектура

```
engine/client/cl_steam_presence_slayer.c     когда играем (cls.state == ca_active)
        │ JNI: steamPresenceStart/Stop/Shutdown/Available
        ▼
XashActivity (мост)
        ▼
su.xash.engine.steam.SteamPresence           свой поток, логон/heartbeat/reconnect
        ├── SteamCM          сессия с CM: кадры, заголовок, Multi+gzip, ClientGamesPlayed
        ├── SteamWebSocket   RFC 6455 поверх TLS (wss://…/cmsocket/)
        ├── SteamAuth        token-flow: QR / пароль → refresh_token
        └── SteamWire        protobuf wire format + base64, без зависимостей
                             ▲
        SteamAuthActivity ───┘  экран входа (QR в приложении Steam / пароль + Guard)
```

Движок не ждёт сеть никогда: он отдаёт намерение («играю в это, на таком
сервере») и продолжает кадр. Сообщение уходит только на изменение — иначе это
был бы JNI-вызов и protobuf каждый кадр ради сведений, которые меняются
несколько раз за сессию.

### Почему статус гаснет сразу, а не через минуту

Первая живая проверка дала жалобу «вышел из игры, а в профиле всё ещё играю;
через минуту пропало». Минута — это и есть диагноз, и Steam тут не виноват.

`SteamCM.pump(int timeout)` принимал таймаут и **игнорировал** его. Сокет
создаётся с `setSoTimeout(45_000)` — столько CM может законно думать над
логоном, — и поток presence, вызывая `pump(1000)`, засыпал внутри чтения на все
45 секунд. Движок сообщал «карта закончилась» мгновенно; обработать это было
некому, пока чтение не вернётся.

Замерено на живой сессии, до и после:

| Вызов | Было | Стало |
|---|---|---|
| `pump(1000)` | 45017 мс | 1002 мс |
| `pump(200)` | — | 201 мс |

Таймаут теперь ставится **на вызов** и возвращается обратно, потому что тот же
сокет обслуживает логон: единый дедлайн в секунду сломал бы вход, а единый в 45
— снятие статуса. Проверяется таймингом в `compile_steam_cm.sh`, а не
комментарием: баг был невидим для всех остальных тестов — ничего не падало,
поток просто опаздывал.

Отсюда же следствие для чтения профиля друзьями: «Присоединиться» в их меню
после твоего выхода — та же залипшая сессия, вид с другой стороны, а не
отдельная поломка rich presence.

### Решения, которые стоит помнить

**WebSocket, а не сырой TCP.** У сырого TCP к CM свой handshake:
`ClientEncryptRequest`, RSA к захардкоженному ключу Valve, дальше AES-256-CBC с
HMAC. У `wss://` то же самое лежит внутри TLS — шифрование делает системный
стек, своего криптокода нет вовсе. Для security-чувствительного пути это
решающий довод.

**Свой protobuf, а не protobuf-javalite.** Нужны шесть сообщений из скалярных
полей. Javalite — это codegen-плагин, `.proto`-исходники и новый шаг
разрешения зависимостей в сборке, которая является единственным каналом
получения APK. Wire format — поток тег/значение; закодировать его руками
оказалось меньше кода, чем обвязка сборки. Правильность проверяется не «сам с
собой»: `steam_wire_crosscheck.py` парсит байты Java-писателя настоящим Google
protobuf по определениям Valve.

**Свой WebSocket.** В Android его нет (Java 11 HttpClient недоступен), иначе —
OkHttp в зависимости. Нужная половина RFC 6455 (кадры, маскирование,
ping/pong, close) ≈ по объёму та же обвязка, но, в отличие от зависимости,
запускается на десктопном JVM без Android.

**Без WebView на входе.** Форма логина внутри WebView, которым управляет
приложение, — ровно форма фишинга учётных данных. Вход идёт через приложение
Steam (ссылка `s.team/q/1/<client_id>`, её перехватывает Steam) или через
`api.steampowered.com` по HTTPS. На том же устройстве, что показывает QR,
просить сфотографировать свой экран абсурдно — поэтому ссылка открывается
напрямую, а QR остаётся текстом для случая «подтверждаю с другого устройства».

### Ловушки протокола (проверено на живом Steam)

- **Легаси-вход мёртв.** `ClientLogon` с паролем всегда отдаёт EResult 5, для
  любого аккаунта. Рабочая схема: `BeginAuthSessionViaQR`/`ViaCredentials` →
  `PollAuthSessionStatus` → `refresh_token` → `ClientLogon` с
  `access_token=<refresh_token>` (поле 108).
- `GetPasswordRSAPublicKey` — **GET**, на POST отвечает HTTP 405. Ошибка легко
  читается как «аккаунт отвергнут», потому что следующий запрос не случается ни
  в том, ни в другом случае.
- Код результата — в **заголовке** `x-eresult`, не в HTTP-статусе: отказ логина
  приходит с honest HTTP 200.
- Эти вызовы работают только по HTTP. Через CM до логона ответа нет вообще —
  что логично, сессии для маршрутизации ответа ещё не существует.
- `EOSType` отрицателен (`Linux4x = -192`), а `client_os_type` — uint32:
  нужна маска `& 0xFFFFFFFF`, иначе protobuf ругается «Value out of range».
- При отказе логона Steam **рвёт соединение вместо ответа**. «Нет ответа» — это
  и есть диагноз, и сообщение должно так и говорить.
- `client_id` — uint64; у Steam регулярно взведён старший бит, и Java печатает
  его отрицательным. На проводе всё верно, но в тексте нужен
  `Long.toUnsignedString`.
- `Multi` (EMsg 1) заворачивает несколько сообщений в один кадр, часто
  gzip'нутый, и ответ на логон обычно приходит внутри него. Разбор Multi не
  опционален.

## Пользоваться

Настройки лаунчера → **Steam account** → войти (подтвердить в приложении Steam
или ввести имя и пароль). Рядом переключатель **Show what I'm playing**.

Консоль движка:

| Команда / cvar | Что делает |
|---|---|
| `slayer_steam_presence_status` | показывает, активен ли статус, и если нет — почему |
| `slayer_steam_presence` (1) | выключатель |
| `slayer_steam_presence_server` (1) | показывать ли адрес сервера |
| `slayer_steam_presence_name` ("") | свой заголовок вместо названия мода |

Приватные адреса (127/8, 10/8, 192.168/16, 172.16/12) и одиночная игра
показывают статус **без** адреса: читателю профиля он бесполезен, а
публиковать свой локальный адрес незачем.

## Тесты

Все запускаются в песочнице, без устройства и без Android SDK.

| Скрипт | Что проверяет | Результат |
|---|---|---|
| `compile_steam_wire.sh` | protobuf-кодировщик; **кросс-проверка** байтов настоящим Google protobuf | 22 PASS + CROSS-CHECK OK |
| `compile_steam_auth.sh` | token-flow против **живого** `IAuthenticationService` | 12 PASS |
| `compile_steam_cm.sh` | полная сессия с **живым** CM (анонимный логон): список серверов, TLS, WebSocket, кадры, Multi+gzip, heartbeat, **и тайминг `pump()`** | 28 PASS |
| `compile_steam_presence.sh` | `SteamPresence` против стабов Android: что считается «готово», неблокирующий `start()`, выход из аккаунта | 21 PASS |
| `compile_presence.sh` | конечный автомат движка: одно сообщение на изменение, фильтр адресов | 35 PASS |
| `compile_presence_jni.sh` | компиляция **JNI-ветки** движка (её `compile_presence.sh` не трогает) | SYNTAX OK ×2 |
| `compile_steam_authui.sh` | компиляция `SteamAuthActivity` против стабов framework | COMPILE OK |
| `jni_signature_check.py` | дескрипторы JNI в C против Java-методов + правила R8 | 8 lookups, 0 проблем |
| `kotlin_reference_check.py` | ссылки Kotlin в Java-классы, `R.string.*`, ключи настроек | 0 проблем |

Почему отдельно `jni_signature_check.py`: C резолвит метод по имени **и
дескриптору** в рантайме, поэтому расхождение — не ошибка сборки нигде.
`GetStaticMethodID` просто вернёт NULL, и фича молча ничего не делает. Ровно
так в этом проекте уже терялся `getSteamId` после R8.

**Что не проверено:** реальный вход в реальный аккаунт и появление зелёного
статуса в профиле — для этого нужны твои учётные данные. Всё до этой точки
(включая протокол на живых серверах Steam) проверено.

## Ограничения

- Steam держит одну игровую сессию на аккаунт: игра на ПК вытеснит статус.
- `refresh_token` = полный доступ к аккаунту. Лежит в `SharedPreferences`
  приложения (приватные для приложения). Выход из аккаунта его удаляет.
- Часы идут в «Counter-Strike», но это не то же, что учёт наигранного времени
  самим клиентом Steam.
